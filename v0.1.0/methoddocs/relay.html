Relay#

Async WalletConnect irn relay client.

class walletconnect.relay.RelayClient(project_id: str | None = None, *, relay_url: str = 'wss://relay.walletconnect.org', auth_key: AuthKeyPair | None = None, origin: str | None = None, user_agent: str = 'walletconnect-py/0.x', request_timeout: float = 30.0, auto_reconnect: bool = True, reconnect_min_delay: float = 0.5, reconnect_max_delay: float = 30.0, reconnect_max_attempts: int | None = None)#

Bases: object

Minimal async irn relay client (dApp / publisher+subscriber side).

Typical use:

client = RelayClient(project_id="...")
await client.connect()
sub_id = await client.subscribe(topic)
await client.publish(topic, envelope, ttl=300, tag=1100)
...
await client.close()

Auto-reconnect (on by default): if the WebSocket drops for any reason other than close(), the client reconnects with exponential backoff (reconnect_min_delay doubling up to reconnect_max_delay, with jitter), signs a fresh auth JWT, re-subscribes every topic and runs irn_fetchMessages on each so messages published while offline are still delivered to on_message() handlers (they may see a message twice; dedupe upstream). Relay requests made while disconnected, or in flight when the socket dropped, are re-sent once the connection is back (publish/subscribe are idempotent on the relay); if it is not back within request_timeout they raise RelayDisconnectedError.

async request(method: str, params: dict[str, Any] | None = None, *, retry: bool = True) → Any#

Send a JSON-RPC request and wait for the matching response.

If the connection is down (or drops before the response arrives) and auto-reconnect is running, waits for it and re-sends, all within request_timeout. Pass retry=False to fail fast with RelayDisconnectedError instead.

class walletconnect.sign.SignClient(project_id: str | None = None, *, metadata: Metadata | dict[str, Any] | None = None, relay_url: str = 'wss://relay.walletconnect.org', state: ClientState | None = None, on_state_change: Callable[[ClientState], Awaitable[None] | None] | None = None, origin: str | None = None, connect_timeout: float = 300.0, request_timeout: float = 300.0, auto_reconnect: bool = True, auto_extend: bool = False, auto_extend_threshold: float = 172800, expiring_warning: float = 86400, maintenance_interval: float = 3600)#

Bases: object

Async dApp-side WalletConnect Sign client.

metadata identifies your app to the wallet (sent as proposer.metadata in wc_sessionPropose). Accepts a Metadata or an equivalent dict; defaults to Metadata.default().

state resumes a previous client: its relay identity key and settled sessions (see ClientState). Without it, the client starts with a fresh relay key and no sessions. The client copies state; read the current state back with export_state(). Nothing is ever written to disk by the library.

on_state_change (optional) is called with a fresh ClientState snapshot whenever the persistable state changes (session settled, updated, extended, deleted or expired), so you can save it.

auto_reconnect (default True): if the relay WebSocket drops, reconnect with capped, jittered backoff, re-subscribe every session/pairing topic and fetch anything published meanwhile. Wallet requests in flight keep waiting (their responses are queued by the relay); relay calls made while down are re-sent once reconnected, or raise RelayDisconnectedError if the relay is not back within the relay request timeout.

Long-running sessions (see the “Long-running sessions” guide):

  • Register event handlers with on() (session_update, session_event, session_delete, session_expire, session_extend, session_expiring, relay_disconnect, relay_reconnect).

  • Expiry is checked on load, before every request, and by a local timer; requests waiting on a session that expires or is deleted fail right away.

  • extend() asks the wallet for 7 more days. With auto_extend=True the client does it on its own once less than auto_extend_threshold seconds (default 2 days) remain, retrying every maintenance_interval (default 1h) until the wallet confirms; it logs a warning and emits session_expiring once less than expiring_warning (default 24h) remains unconfirmed.

  • is_reachable() pings the wallet and marks the session unreachable (not deleted) when it does not answer.

async connect(*, chains: Iterable[int] = (1,), methods: Iterable[str] = ('eth_sendTransaction', 'personal_sign', 'eth_signTypedData_v4'), events: Iterable[str] = ('chainChanged', 'accountsChanged'), optional_namespaces: dict[str, ProposalNamespace | dict[str, Any]] | None = None) → tuple[str, Task[Session]]#

Start a session proposal on a new pairing.

Returns (uri, session_task). Print/QR the URI, then await session_task (or use wait_for_session()) until the wallet settles. Several proposals may be in flight at once; each has its own pairing topic (PairingURI.parse(uri).topic).

async disconnect(reason: str = 'User disconnected', *, topic: str | None = None) → None#

End a session: notify the wallet (wc_sessionDelete) and forget it.

With no topic this ends the only active session (no-op when there is none). The relay connection stays open; call close() to shut it down.

export_state() → ClientState#

Return a snapshot of the persistable state (relay key + settled sessions).

Serialize it with state.model_dump_json() (or state.save(path)) and pass it back as SignClient(state=ClientState.model_validate_json(...)).

Warning

The snapshot contains secret keys. Store it securely.

async extend(*, topic: str | None = None, timeout: float | None = None) → int#

Ask the wallet to extend the session by 7 days (wc_sessionExtend).

The new expiry (now + 7 days) is applied only once the wallet replies true; returns it. Raises WalletConnectTimeoutError if the wallet doesn’t answer within timeout (the session is left unchanged), or the wallet’s SdkError. Concurrent calls share one request.

async is_reachable(*, topic: str | None = None, timeout: float = 10.0) → bool#

Ping the wallet; return False (and mark the session unreachable) on timeout.

An unreachable session is not deleted: the phone may just be offline or the app backgrounded, and the relay keeps queued requests for it. The mark clears as soon as any message arrives from the wallet. Relay errors (not the wallet’s fault) still raise.

off(name: str, handler: Callable[[ClientEvent], Awaitable[None] | None]) → None#

Remove a handler registered with on() (no-op if it isn’t registered).

on(name: str, handler: Callable[[ClientEvent], Awaitable[None] | None] | None = None) → Any#

Register handler for event name (or "*" for all events).

Handlers get a ClientEvent; they may be sync or async and run as tasks on the client’s loop. Returns the handler. Also usable as a decorator:

@client.on("session_delete")
def gone(event): ...
async open() → None#

Connect to the relay and resume restored sessions (idempotent).

Subscribes every session topic and fetches messages the relay queued while this client was offline. Called automatically by connect(), request() and ping(); call it yourself to start receiving wallet messages for restored sessions right away.

class walletconnect.sign.SyncSignClient(project_id: str | None = None, *, metadata: Metadata | dict[str, Any] | None = None, relay_url: str = 'wss://relay.walletconnect.org', state: ClientState | None = None, on_state_change: Callable[[ClientState], Any] | None = None, origin: str | None = None, connect_timeout: float = 300.0, request_timeout: float = 300.0, auto_reconnect: bool = True, auto_extend: bool = False, auto_extend_threshold: float = 172800, expiring_warning: float = 86400, maintenance_interval: float = 3600)#

Bases: object

Thread-friendly wrapper for scripts and CLIs.

Starts a background asyncio loop so relay keepalives and subscription acks continue while the main thread blocks on connect() / request().

Takes the same state= / on_state_change= arguments as SignClient (on_state_change runs on the background loop thread).

Event handlers registered with on() also run on the background loop thread, so keep them quick and thread-safe (e.g. put the event on a queue.Queue).
